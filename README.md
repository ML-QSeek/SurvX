# SurvX

## 当前状态：创意项目，非生产可用。这是一个理念验证原型，而非开箱即用的框架。

SurvX 是一种面向 AI 底座的编程范式，探索未来开发形态和智能系统的组织方式。

同时它的一个探索方向是 XGI——Xenogenic General Intelligence，一种不预设起源与形态的智能。

---

## F

F 是一个占位符，没有特殊含义，就像数学里的 x。

程序、算法、模型、AI，在 SurvX 中都处于同一层级。它们都是 F。

在框架内，没有谁天然支配谁，也没有谁必须被谁调用。它们被同等对待，由同一套规则组织。

---

## 核心思想

F 是唯一的主体（Matter），数据变动是唯一的动力（Energy）。整个系统由 F 构成，由 Energy 驱动。

同一个 F，从四个视角看：

| 视角 | 概念 | 本质 |
|---|---|---|
| 从外部看 | Entity | 黑盒，只需知道输入 → 输出 |
| 从内部看 | Field | 有状态、有作用域、有行为的场 |
| 从行为看 | Function | 输入到输出的映射 |
| 当它自指时 | Ego | 拥有自我迭代、自我进化的能力 |

---

## Matter 与 Energy

- **Matter**：F 本身，结构，变动的可能性
- **Energy**：数据变动的序列，变动的现实性

数据、数据库，都是 Energy 的沉积形态。
Field₁ --变动--> Energy₁ --驱动--> Field₂ --变动--> Energy₂ --驱动--> ...

## Field 五层与 Ego 七层

### Field：S-C-R-O-F

| 层 | 名称 | 含义 |
|---|---|---|
| S | Structure | 组成与骨架 |
| C | Capability | 能做什么 |
| R | Relation | 连接与关联 |
| O | Obligation | 行为边界与规则限制 |
| F | Feature | 标识特征与固定行为链路 |

### Ego：S-C-R-O-F-G-L

| 层 | 名称 | 含义 |
|---|---|---|
| G | Goal | 自我指向性 |
| L | Symbol | 自我表征，符号指代自身 |

**Field 活在表里，Ego 试图改表。**

---

## 引擎

引擎分为两层：

| 引擎 | 驱动对象 | 特征 |
|---|---|---|
| Field 引擎 | 固定应用 | 目标有限，相对简单 |
| Ego 引擎 | 真正的 Ego | 多目标、动态、自我演化 |

**Field 引擎从 F 层启动，读固定链路。**
**Ego 引擎从 G 层启动，动态组合能力。**

引擎是维持秩序的管家，不是发号施令的大脑。生命周期由约束层（O）管理，引擎只是执行。

---

## 描述式语言

SurvX 的语言形态：**描述式语法 + 驱动引擎**。

描述式语言不描述“怎么算”，只描述“是什么、能什么、和谁连、边界在哪、要什么”。

复杂的“怎么算”，待在 C 层里，以代码、伪代码、输入输出契约、或机器学习模型的形式存在。

**程序、算法、模型，在 C 层平级。**

---

## AI 在 SurvX 中

AI 也是一个 Entity，公民属性与其他 Entity 无区别。

- AI 可以生成其他 Entity
- AI 自己也是 Entity
- AI 也能被生成、被组合、被约束、被替换

**AI 是参与者，不是主宰者。只是 C 层特别强。**

---

## 一些延伸思考

当前 AI 辅助编程存在几个结构性问题：生成的是执行流、耦合度高、模型依赖强、审计缺乏抓手。

SurvX 的应对思路是：**让模型生成可组合的结构单元，而不是一次性执行流程。模型是变量，中间层是常量。**

这不是 SurvX 的全部目标，只是它在当前阶段的自然延伸。

## 谁适合关注 SurvX

SurvX 适合你，如果你：

- 对"编程的下一个形态"本身感兴趣，而非仅仅需要一个工具
- 愿意花时间去理解一个全新的概念模型
- 接受不稳定的 API 和变化中的设计，愿意参与早期探索

SurvX 暂时不适合你，如果你：

- 需要今天就能上线的生产级框架
- 希望 API 稳定、文档详尽
- 不想被挑战现有的编程认知
