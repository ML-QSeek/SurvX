# Q-IIO-schema

**文档定位**：Q 函数设计阶段的 prompt schema，供人机交流使用。规定复杂 Q 设计时必须描述哪些内容，区别于 `syntax_zh.md`（写出来要合法）和 Q 文件本身（实现）。

**适用**：一般 Q 用 `# prompt:` `# reason:` 注释即可；复杂 Q 用本 schema 完整描述。

**受约束于**：`syntax_zh.md` 第四部分编码原则。

---

## 一、Lang

> 目标语言：函数用什么语言实现。

- **语言**：Python / Rust / HTML / JavaScript 等
- **版本**：语言版本
- **风格/规范**：遵循 `syntax_zh.md` 第四部分编码原则，如有额外约定在此补充

## 二、I - Import

> 输入是什么：函数接收什么、依赖什么、前置条件是什么。

- **数据类型（结构态）**：定义输入数据的结构体、字段规范、嵌套格式，统一数据外壳
- **数值范围（值态）**：定义输入取值边界、阈值区间、合法值域，完成基础数据校验
- **状态标识（逻辑态）**：定义输入的前置条件、状态要求
- **时间与频率（时序态）**：定义输入的调用节奏、频率限制、超时规则
- **环境交互（环境态）**：追踪输入来源、外部依赖、环境上下文
- **元数据（描述态）**：承载输入备注、版本信息、归属实体等附加描述信息

## 四、O - Output

> 输出是什么：返回什么、格式如何、有什么副作用、怎么处理错误。

- **数据类型（结构态）**：定义输出数据的结构体、字段规范、嵌套格式，统一数据外壳
- **数值范围（值态）**：定义输出取值边界、阈值区间、合法值域，完成基础数据校验
- **状态标识（逻辑态）**：定义执行成功、失败、中断、待处理等业务状态标签，标识运行结果
- **时间与频率（时序态）**：定义输出节奏、时效、超时规则
- **环境交互（环境态）**：追踪输出流向、副作用、外部依赖、环境上下文
- **元数据（描述态）**：承载输出备注、版本信息、创建时间、归属实体等附加描述信息
