# SurvX 蓝图描述语法规范（syntax_zh.md）

## 1. 概述

本文档定义 **SurvX Instance 实例蓝图** 全套标准化描述语法、存储范式、层级规则、表结构约束与校验规范，为 SurvX 引擎、AI 建模协作、实例迭代演化提供唯一统一的语法标准。

蓝图为**声明式结构描述体系**，非可执行编程语言，核心用于定义实例的实体构成、分层结构、功能能力、关联关系、约束边界与备选执行路径。

### 1.1 依赖与定位

- 语义规则完全源自 SurvX 核心元模型（core-content），语法层与元模型层严格对齐；

- 本文档为 **AI 官方上下文规约**，所有 AI 建模、解析、修改、推演行为必须遵循本规范；

- 引擎底层算法、事务逻辑、F 构件实现不纳入本文档范围，属于引擎内置执行层，对 AI 透明。

### 1.2 核心范式原则

Field、Env、Ego 均归属 Matter 实体大类，**所有 Matter 子类完全复用同一套基础书写语法模板**。子类差异（可用分层、语义规则、能力边界）由元模型定义，语法层保持统一，无差异化语法。

### 1.3 两种项目形态

#### 1.3.1 简洁开发形态（原型/调试）

基于独立 Python 文件开发，所有 Matter 实体、Energy 结构通过 Python 字典声明描述，无数据库依赖，支持快速迭代、原型验证、小规模实例调试。

#### 1.3.2 正式生产形态（长期维护）

采用**多介质分离存储架构**，实现结构、功能、数据解耦：

- 静态蓝图元结构（Matter 结构化定义）：持久化至 SQLite；

- Feature（F）功能逻辑：独立文件系统存储，与数据库元数据建立映射；

- Energy 时序数据、参数/阈值快照：存储至 DuckDB，支撑时序查询、状态回放、演化追溯。

## 2. 实例顶层结构定义

### 2.1 整体结构公式

`Instance = Cat + (Cat)<egoname> + [Cat]<envname> + {Cat}<energyname>`

### 2.2 顶层标记规范

`()` / `[]` / `{}` 为蓝图顶层固定语义标记，属于字典字符串 Key，非程序变量，可合法存入字典与数据库文本字段。

- `(Cat)`：Ego 主体实体标记

- `[Cat]`：Env/Field 环境实体标记

- `{Cat}`：Energy 能量参数实体标记

### 2.3 原生简写规范（系统默认基座）

- `(Cat)base` 简写为 `()Cat`

- `[Cat]base` 简写为 `[]Cat`

- `{Cat}base` 简写为 `{}Cat`

标记支持单实体与多实体集合写法：单实体 `(name)xxx`、多实体 `[name1,name2,name3]xxx`；实体标识符禁止使用逗号，避免解析歧义。


> 示例示意（仅用来理解，不是完整语法）

Instance = {
    "Cat": {...},
    "(Cat)<egoname>": {...},
    "[Cat]<envname>": {...},
    "{Cat}<energyname>": {...}
}



## 3. 实体分层与标识规范

### 3\.1 Matter 标准七层分层

所有 Matter 实体统一拥有 S/C/R/O/F/G/L 七层分层，Energy 无分层能力：

- S 结构层、C 功能层、R 关系层、O 约束层、F 特征层、G 目标层、L 符号层

### 3.2 构件标识规则

构件标识采用 `构件名_分层标签` 格式，存储为字典字符串 Key。通过 `rsplit("_",1)` 拆分，构件名在前、分层标签在后；构件名内部可使用下划线，分层标签固定为 S/C/R/O/F/G/L。

## 4. 底层存储核心范式

### 4.1 双字典扁平存储架构

全局采用 **扁平主数据字典（data_store）+ 标签索引字典（tag_index）**，无深层嵌套字典，所有节点平铺顶层，通过字符串 Key 拼接表达层级关系。

#### 4.1.1 节点 ID 规则

- 子节点采用**自增数字 ID**，ID 分配后默认永久不回收；

- 新增节点末尾追加，无连锁结构改动，保证系统演化稳定性。

#### 4.1.2 节点操作规范

- **删除节点**：业务层仅修改本节点 `active=False`，底层内核保留物理删除能力（仅后台维护使用）；同步更新 data_store 与 tag_index；

- **重编号节点**：仅后台维护脚本可用，上层业务禁止调用；重编号时更新父节点引用、批量迁移下级所有分支 Key 与双字典数据；

- **索引同步**：tag_index 与 data_store 一一对应，存储节点语义标签，检索依赖标签过滤，无需反复解析 Key。

### 4.2 节点启停（active）机制

取消业务层物理删除，所有节点生命周期由 active 布尔字段管控（存储于 tag_index）：
- active=True：节点生效，参与 tick 运算、遍历、约束校验；
- active=False：节点休眠，默认视图隐藏，原始数据、版本记录完整保留。

第一版实现规则：仅修改目标节点自身 active 状态，子节点状态独立保留。
祖先节点休眠不会自动将后代节点判定失效；是否需要连带失效，由版本更新或业务逻辑按需决定，不作为底层默认规则。


#### 4.2.1 双查询模式

- 默认查询：仅返回 active 全链路生效的有效节点；

- 高级查询（`include_inactive=True`）：返回全量节点，包含休眠节点，用于历史回溯、节点复用激活。


### 4.3 版本控制规则

- 所有参数、约束、关系记录自带自增正整数 `version` 版本号；

- 每次更新生成新版本记录，旧版本永久保留，不物理删除；

- 系统默认读取当前最大有效版本，实现无感知迭代更新。








## 5. 三大基础核心数据表

系统底层唯一物理存储表，所有层级、能力、状态均由三张表数据聚合生成（数据驱动架构），表名统一后缀：`_parameter`、`_constraint`、`_relation`。

### 5.1 通用核心字段（三表统一）

- **id**：单记录全局唯一固定 ID，创建后永不修改，作为永久引用标识；跨表引用带前缀：`param:`、`constraint:`、`rel:`

- **context_path**：节点生效上下文路径 Key，限定当前记录的作用域，实现同构件多上下文数据隔离；支持向上回溯上层定义、下层覆盖上层规则

- **subject**：作用主体实体 ID，指代当前参数/约束/关系的发起对象

- **version**：自增版本号，用于迭代追溯、版本复用

- **value**：核心取值字段，支持两类类型：① 字面量（数字、字符串、布尔）② F 构件引用（运行时动态计算取值）

### 5.2 分表专属字段

#### 5.2.1 _parameter 参数表

字段：id、context_path、subject、name（概念实体ID）、value、version

#### 5.2.2 _constraint 约束表

字段：id、context_path、subject、name（约束概念ID）、value（阈值/规则）、version

#### 5.2.3 _relation 关系表

字段：id、context_path、subject（因/发起实体）、effect（果/作用实体）、version

### 5.3 核心引用规约（强强制）

**逻辑层禁止裸字符串**：context_path、subject、name、effect 所有定位字段，必须引用系统预构建的实体/概念 ID，禁止直接写入自定义字符串。

所有参数名、约束名、关系主体，必须先完成抽象概念构件建设、生成唯一ID，方可被三表记录引用。


`value` 字段的内容不局限于普通数字、字符串，**也可以指向一个 F 构件**。

也就是两种类型：

1. 基础字面量：数值、文本、布尔等普通常量
2. 引用类型：指向体系内 F（Function）构件，代表这个参数 / 约束的值由该 F 计算得出




### 新增字段：`version`

含义：版本号，纯自增正整数。
规则：

1. 每次更新同一条记录，生成新的`version`，旧版本记录保留，不做物理删除。
2. 读取逻辑：默认取该记录下最大版本号；若无新版本，则沿用已有旧版本。






## 6. 层级逻辑架构（数据驱动）

S/C/R/O/F/G/L 七层**非物理表**，全部为**基于三表数据聚合的 F 逻辑视图**，引擎通过通用能力组合数据，涌现系统能力，无需修改底层代码即可迭代模型。

### 6\.1 七层层级递进关系

1. **结构层S**：实体基础结构定义，所有节点载体

2. **关系层C**：聚合\_relation表数据，定义实体间因果关联（复合F）

3. **约束层R**：聚合\_constraint表数据，定义实体运行边界、阈值规则（复合F）

4. **功能层F**：所有计算单元合集，包含公式、视图、神经网络模型，支撑参数动态计算

5. **特征层O**：聚合关系、约束、功能层能力，为 Matter 统一调用入口，定义实体核心使用路径

6. **目标层G**：全局检索三表全量数据，涌现候选目标池；Ego 在此筛选、权衡、优化目标，驱动系统演化

7. **符号层L**：唯一允许裸字符串的层级，负责ID与自然语言/自定义契约的双向翻译，仅用于对外交互，不参与内部推演计算






F 是统一抽象的计算单元，**它不限制内部实现**：

- 轻量 F：简单数学表达式、条件判断，比如 `健康度 = 血氧 - 损耗值`
- 复合 F：批量筛选组合多张基础表的记录，也就是我们刚才说的逻辑视图（呼吸系统这类系统）
- 神经网络 F：内部是神经网络模型，输入一组特征 ID 对应的值，输出一个数值向量或者标量



### 6\.2 实体入口规则

- Field/Env 普通实体：核心入口为**特征层O**，调用即加载全量状态与约束能力

- Ego 主体实体：核心入口为**目标层G**，以目标筛选与全局优化为核心行为

### 6\.3 Ego 与 Field 双向关联规则

Ego 七层结构与 Field 五层结构为**独立合并、双向绑定**，非共享复用：

- Field 功能层：定义生理/实体状态 → 主观特征的映射关系

- Ego 功能层：定义主观情绪/认知 → 实体状态的反向调控关系

两套独立 F 构件形成闭环因果，实现身心双向影响的演化逻辑。

## 7\. 约束表达式归一化规则

不新增数据库字段，通过 value 字段内嵌区间符号实现约束规则归一化，引擎底层仅需实现一套「小于」原语，降低运算复杂度。

### 7\.1 符号定义

支持`()`、`[]`、`(]`、`[)` 区间符号，内嵌于 value 字段字符串中。

### 7\.2 表达式归一化算法

固定主体 A（subject\_value）位置不变，通过符号变换统一为 `A' < T` 格式：

- A \< T → 原生表达式

- A ≤ T → A \< T \+ ε

- A \> T → \-A \< \-T

- A ≥ T → \-A \< \-T \+ ε

- A == T → \(A \< T\+ε\) AND \(\-A \< \-T\+ε\)

## 8\. 系统全量表结构规范

所有表统一规则：单表 ID 唯一，**表名\+ID** 为全局唯一索引标识；核心运算仅依赖结构化ID与字段，附加元信息不参与计算。

### 8\.1 引擎基础核心表（运行必需）

- **状态表**：存储当前 tick 窗口全量变量，为引擎实时计算的唯一数据源；tick 结束后数据归档分流，窗口刷新重置

- **序列表**：存储需持续追踪的时序核心指标，按 tick 逐条追加，用于趋势分析、时序回溯

- **经历表**：tick 截面快照，仅存储当前截面 active 生效条目；自带版本号，历史回溯无需区分「不存在/未激活」，active 状态仅作用于实时运算

- **注册表**：全局实体标识注册中心，用于仿真空间、长key标签、自定义实体的注册绑定、去重校验

### 8\.2 Ego 专属认知表

- **意图表**：存储 Ego 基于目标筛选、约束求解得到的可行路径与执行意图

- **反馈表**：存储意图执行全过程的实时反馈数据，用于认知迭代、目标修正

- **语言表**：支撑符号层与参数约束解析，存储短句范式、符号表征、特征组合、习惯表达

- **训练数据表**：聚合系统内全表数据\+外部数据，为模型训练、Ego 总结反思、认知升级提供数据源

### 8\.3 上层观测非基础表（非运行必需）

**报告总结表**：系统综合 Dashboard 观测面板，不参与底层 tick 流转与引擎核心运算。

核心能力：① 聚合全表核心指标，供人机观测；② 支撑 Ego 虚拟推演（脑海试运行），存储假想实验观测结果，用于方案自检、择优迭代；③ 区分真实运行数据与虚拟推演数据，避免认知混淆。

## 9\. AI 协作字段规范

所有表、所有层级**可按需新增 AI 交互元信息字段**，字段特性：

- 存储内容：自然语言描述、功能说明、Prompt 关键字、设计意图、场景约束；

- 运行边界：**完全不参与引擎计算、约束校验、tick 流转、跨表解析**，仅作为 AI 阅读理解的辅助元数据；

- 配套支持：可按需新增内部特殊字符标记字段，用于系统内部识别分类，不污染核心ID与运算体系。

## 10\. 核心建模约束与校验规则

### 10\.1 强制建模原则

- **禁止孤立节点**：新增任何实体、参数、F 构件，必须绑定关联关系、作用域、约束，无关联节点校验不通过，禁止入库；

- **先定义后引用**：所有概念、实体、参数标签必须预先构建生成ID，方可被三表记录引用；

- **逻辑层无裸文本**：仅符号层允许自然语言与自定义契约文本，所有运算、关联、约束全部依赖ID引用。

### 10\.2 依赖与循环校验

- 允许双向因果 F（情绪↔生理）闭环关系；

- 禁止无限递归 F 调用，引擎底层自动拦截非法递归依赖。

### 10\.3 实体类型校验

- 仅 Matter 实体拥有 S/C/R/O/F/G/L 七层分层；

- Energy 实体无分层能力，仅存储参数、时序、能量快照数据。

### 10\.4 版本引用规则

全局 F 构件引用绑定固定版本，新版本发布不自动升级存量引用，版本迭代需人工显式切换，保证实例运行稳定性。

## 12\. 引擎核心承载边界

以下能力为引擎底座固有职责，无需AI理解、不纳入上下文，由底层代码固化实现：

- 统一 **表名\+ID** 跨表引用解析器；

- tick 窗口切换、状态表归档事务一致性保障；

- F 构件底层算法实现、运算调度、递归拦截；

- 双字典增删改查、版本管理、active 状态同步。

## 13\. 人机\-AI 协作建模流程

1. 人工输出场景需求、顶层蓝图构想；

2. 人机协同梳理实体结构、分层能力、关联约束、目标方向；

3. AI 依据本规范，结构化拆解为实体、三表记录、F 构件；

4. AI 完成语法校验、ID 关联、版本初始化，写入底层存储；

5. 引擎加载数据，启动 tick 推演、Ego 目标优化与虚拟推演；

6. 基于报告表观测结果，迭代优化蓝图结构与参数约束，持续演化。

**分工边界**：人工把控顶层蓝图与核心逻辑，AI 承担结构化落地、语法校验、批量建模、迭代运维工作；Ego 远期原生符号能力与外部AI助手能力相互独立、并行共存。

> （注：部分内容可能由 AI 生成）

4. 组件复用：只读走引用；如果需要修改，则深度拷贝生成独立副本。
5. 语法底层：长路径扁平 key，局部数字序号，不用深层嵌套字典；所有结构最终编译到 `_parameter` / `_constraint` / `_relation`。


引擎不完全支持脚本模式  正式模式  引擎是完整的

简易脚本可以读取正式项目；回写属于手动局部合并，简易脚本不维护全部持久化后台逻辑。

相关记录一条一条增加 不做为一个大字典 同时增加很多字段，维持动态更新 自由更新 灵活更新


所有增、删、改操作统一封装引擎接口，业务层不直接操作底层两个字典。依靠字符串前缀匹配实现分支定位，规避递归遍历，实现逻辑简单可控。









# Appendix：关键字清单 & 校验规则（精简公式版）

> 
> 附录归属：syntax.md
> 风格：条目化、公式化，减少长段落

## 1 保留关键字

1. 分层标识关键字：`S, C, R, O, F, G, L`
2. 系统保留字段：`active`
3. 语法符号：`() [] {} _`

## 2 命名语法规则

1. 构件命名格式：`构件名_分层标识`，例：`心脏_S`
2. 字典 Key 允许 `() [] {}`；普通标识符参考 Python 命名规则，允许变通。
3. 子节点 ID：局部自增纯数字 ID。
4. 禁止构件名与保留关键字重名。

## 3 数据结构规则

1. 节点使用 `active` 标记做逻辑启用 / 停用；**无物理删除**。
2. 重编号：属于后台例外维护操作，非常规业务动作。
3. 四张表独立存储：结构表、参数表、约束表、关系表，通过节点 ID 关联，不合并字段。
4. 禁止孤立节点：新增节点必须绑定对应参数、约束、关系；后续可增量补充。

## 4 节点变更规则

1. 新增节点：一次性写入本体，同步写入关联参数、约束、关系。
2. 修改节点 ID：仅递归更新该节点的全部下级路径 Key；上级节点不受影响。

归属：syntax.md
风格：条目化，公式优先，条款清晰，后续可持续增补

## 1 保留关键字

1. 分层标识关键字：`S, C, R, O, F, G, L`
2. 系统保留字段：`active`（布尔，节点生效标记）
3. 语法符号关键字：`() [] {} _`

## 2 命名语法规则

1. 构件标准命名格式：`构件名_分层标识`，示例：`心脏_S`
2. 字典 Key 允许包含符号 `() [] {}`；普通标识符参考 Python 命名规则，允许按需变通。
3. 子节点 ID：局部范围内从 1 开始自增纯数字 ID。
4. 构件名称**不能**与保留关键字重名。
5. 路径 Key：采用下划线拼接层级 ID，用来编码树结构，示例：`root_s_1_s`。
6. 路径 Key 本身等价于结构向量，可直接解析还原层级关系。

## 3 实例顶层语法公式

1. `Instance = Cat + (Cat)<egoname> + [Cat]<envname> + {Cat}<energyname>`
2. 基座简写规则
   - `(Cat)base → ()Cat`
   - `[Cat]base → []Cat`
   - `{Cat}base → {}Cat`
3. 多 Field 集合写法：`[name1,name2,name3]xxx`

## 4 数据存储与表结构规则

1. 四张独立表：结构表、参数表、约束表、关系表；依靠节点 ID 关联，不合并字段，支持动态增删单条记录。
2. 节点生命周期：仅使用`active`标记做逻辑启用 / 停用，**不做物理删除**，保留全部历史记录。
3. 重编号操作：属于后台例外维护操作，不属于常规业务操作。
4. 禁止孤立节点：新增节点时，必须同步写入配套参数、约束、关系记录；允许后续增量补充更多参数与约束。

## 5 节点变更校验规则

1. 新增节点：写入结构表记录的同时，同步写入对应的参数、约束、关系记录。
2. 修改节点 ID：仅递归更新当前节点**所有下级**的路径 Key；上级节点、兄弟节点不受改动影响。
3. 删除（逻辑停用）：仅修改当前节点`active=false`；下级节点不自动变更，由上层业务决定是否批量停用。
4. 索引字典：独立维护标签索引，用于加速检索，和主数据分开同步更新。

## 6 嵌套 Matter 语法规则

1. Matter 统一一套声明语法，Field、Env、Ego 都属于 Matter。
2. 两种引用模式：
   - 模式 A：只引用子 Matter（仅登记引用关系，不展开内部结构）
   - 模式 B：展开子 Matter 完整内部结构描述
3. 采用扁平字典存储，不用深度嵌套字典，全部层级信息编码在路径 Key 内。

## 7 语法校验规则（引擎侧）

1. 校验保留字冲突：构件名称不能匹配任何保留关键字。
2. 校验分层后缀：分层标识只能使用 S/C/R/O/F/G/L。
3. 校验节点完整性：新建节点必须存在至少一条关联关系，不允许无关联孤立节点入库。
4. 校验路径合法性：路径 Key 必须符合层级拼接规则，解析后必须是合法树结构。
5. 校验 active 字段类型：只能为布尔值 true/false。
