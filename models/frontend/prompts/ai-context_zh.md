# commserver — AI 协作说明

## 这是什么

一个独立小工具，SurvX 实例的通讯层。用 FastAPI 承载 HTTP 与 WebSocket，对内跨进程、对外接口统一走它。

核心能力：**动态注册**。

- HTTP：一个名字 = 一个模块 = 一个函数 = 一个路径，运行时能注册、热重载、注销
- WS：一个名字 = 一个 `/ws/{name}` 广播频道，运行时能注册、注销

## 你要做什么

改这个项目时，先理解三件事：

1. **一切围绕「动态注册」**
   不是普通 FastAPI 项目。路由不写装饰器，靠 `app.router.routes` 运行时增删。
   加功能时先问：这是新增一条可注册的能力，还是改核心机制？

2. **内外一套，但别滥用**
   纯函数调用直接 import，不走服务。
   只有「跨进程 / 微服务拆端口 / 加队列广播」才走 commserver。

3. **原型阶段，取舍优先**
   当前实现是为「跑通 + 验证范式」服务的，不追求生产完备。
   加东西前先问：这是原型需要，还是提前做了以后的事？

## 硬约束

改代码时，以下不能破：

- **一个名字 = 模块名 = 函数名 = 路径**，别引入第二套命名规则
- **HTTP 路由走 `APIRoute` + `app.router.routes`**，不要退回 `@app.get` 装饰器
- **WS 频道共用 `broadcast_handler`**，按 path 隔离连接池，不要一个频道一个函数
- **广播只入队不等待**，慢客户端丢消息，不要改成顺序 `await`
- **删路由要清干净**：`app.router.routes` + `_registered` + `openapi_schema`，必要时 `sys.modules` / `_module_cache`
- **第三方依赖（FastAPI / uvicorn）就近引入**，不要渗透到核心结构
- **注释中文、简洁、说「为什么」**，不要写废话注释

## 风格

- 别过度设计。能用字典解决的不用类，能用函数解决的不用装饰器
- 显式优于隐式。一行一条，别合并、别动态拼
- 结构优先。声明性的东西（路由表、频道池）写清楚，别藏在魔法里
- 加功能时保持现有文件结构，不要重排、不要顺手重构

## 别做什么

- 别把这个改成标准 FastAPI 项目（装饰器注册、`include_router`）
- 别引入 ORM、数据库、消息队列框架（原型阶段不需要）
- 别加鉴权、限流、监控（除非明确要求）
- 别把「对内通讯」理解成「所有内部调用都走 HTTP」
- 别为了「更规范」重写已有能跑的代码

## 当前定位

- 阶段：理念验证原型，非生产可用
- 归属：独立 tools，暂未收编进引擎
- 后续：收编时注册表归 Matter.R，由 Energy 驱动

## 用法

见 `commserver.py` 脚本头部 docstring。

## 范式背景（需要时读）

项目背后的 SurvX 范式要点：

- Matter 运行时可变，所以通讯层必须动态注册
- 一切行为由 Energy 数据变动驱动，不由服务主动轮询
- Field.R（关系层）= 对外接口 + 内部模块关系
- 独立小工具不套范式的 Q 命名和五段结构，用有含义的名字

完整范式见 `docs/` 下的设计文档。
