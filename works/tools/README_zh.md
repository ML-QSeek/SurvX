# Tools 目录说明

tools 存放 SurvX 范式的通用工程工具、运行基座、渲染能力、外部适配器。
场景无关、可复用、非业务、非内核，供 examples 与 solutions 按需引用。
不存放业务逻辑、研究方案、范式内核代码。

> 内核定规则，tools 造基建，examples 演能力，solutions 出成果。

## 目录定位

| 目录 | 职责 |
|------|------|
| `survx/` | 范式核心：实体机制、Energy、约束、Ego、事件调度、蓝图解析 |
| `tools/` | 基于内核契约的可插拔工程组件：通讯、连接、数据获取、前端、AI 接入、开发工具 |
| `solutions/` | 业务 / 研究落地（humans、molin），含完整业务逻辑 |
| `examples/` | 轻量 Demo，仅演示范式能力，不做生产交付 |

命名遵循全局约定：目录 snake_case `_`，蓝图字段 kebab-case `-`。

## 工具清单

### CommServer
通信服务。SurvX 实例的通讯层，对内对外统一走 HTTP 与 WebSocket。
HTTP 动态路由：一个名字 = 一个模块 = 一个函数 = 一个路径，启动从 `routes.json` 加载，运行时支持注册、热重载、注销。
WS 广播频道：一个名字 = 一个 `/ws/{name}` 频道，频道隔离，连上的人互相广播。
对应范式：实现 **Field.R（关系层）**，承载实例与外部世界、进程之间的关系。
技术：FastAPI + uvicorn，内存字典管理路由表与频道池，hoc 态无持久化。

### Connectors
连接器。外部接口、数据库等外部资源的集成件。
核心设计：所有外部资源全部建模为「无 Ego 实体」——外部数据库、缓存、消息队列、HTTP/GRPC 接口、第三方算法包、检测模型、外设与传感器。
连接器只做协议转换、状态映射、事件透传，不拥有业务目标、不破坏内核约束。

### FinDataFetcher
金融数据抓取。数据获取类集成件，负责从外部数据源拉取、转换、写入实例。
与 Connectors 同属外部集成，但面向数据获取场景，封装具体数据源的抓取、字段映射与调度逻辑。

### Frontend
前端框架。survx-frontend-web 前端子范式基座。
读取蓝图 UI 声明、自动组装页面、渲染实体面板、实时同步状态、提供沙箱运行环境。
不内置 2D/3D 渲染逻辑，只提供画布嵌入能力。

### LLMGate
AI 集成接口。统一接入大模型能力，供实例与 Ego 推演、蓝图生成、方案评估调用。
AI 仅可操作 Matter 结构化蓝图，禁止篡改执行流、绕过约束层、获取调度权限。

### Studio
开发工作台。项目管理与开发工具，支撑实例创建、蓝图编辑、调试、发布。
对应 `instances/survx_studio/`，是开发者侧的入口。

## 新增工具原则

用到再建、按需增量，不提前预建空目录。
同时满足四条才进 tools：通用、可复用、不绑业务场景、不属于内核逻辑。
