# Tools 目录说明

**Tools** 存放 SurvX 范式的通用工程工具、运行基座、渲染能力、外部适配器。

所有工具**场景无关、可复用、非业务、非内核**，可供 examples 示例、solutions 正式方案按需引用和集成。

本目录只维护通用工程能力，不存放具体业务逻辑、不存放研究方案、不存放范式内核代码。

---

## 核心定位规则

- **survx/ 内核**：范式核心规则、实体机制、Energy、约束、Ego、事件调度、蓝图解析

- **tools/ 工具层**：基于内核契约实现的可插拔工程组件（运行、渲染、对接、前端基座）

- **solutions/ 方案层**：具体业务/研究落地项目（humans、molin），带完整业务逻辑

- **examples/ 示例层**：轻量 Demo，仅用于演示范式能力，不做生产交付

---

## 目录命名规范（全局统一）

- **文件夹目录**：snake\_case 下划线 `_`

- **蓝图内部字段（Energy / Relation / Goal 等）**：kebab\-case 短横 `-`

优势：视觉天然区分「工程文件结构」和「范式实体状态结构」。

## 当前工具清单 \& 职责边界

### 1\. gateway\_fastapi

SurvX 统一运行网关。

负责：实体生命周期管理、事件总线、状态分发、蓝图加载、内外通信中转。

整个范式的运行入口。

### 2\. frontend\_web

前端子范式基座。

负责：读取蓝图 UI 声明、自动组装页面、实体面板渲染、状态实时同步、沙箱运行环境。

**不内置任何 2D/3D 渲染逻辑**，只提供画布嵌入能力。

### 3\. render2d\_web

Web 端通用 2D 渲染工具。

提供画布、点位、连线、精灵、动画、拾取交互，用于仿真可视化、拓扑图、实体空间展示。

可被前端沙箱嵌入，也可独立对接网关。

### 4\. render3d\_web

Web 端通用 3D 渲染工具（预留/可选扩展）。

基于 Three\.js 实现 3D 场景、模型、空间交互。

非主干必需，仅用于高阶演示、视觉展示。

### 5\. external\_connectors

外部系统、存储、第三方算法、协议适配器集合。

**核心设计：所有外部资源全部建模为「无 Ego 实体」**

- 外部数据库、缓存、消息队列、HTTP/GRPC 接口

- 第三方算法包、检测模型、预测工具

- 外设、传感器、外部设备接入

连接器只做**协议转换、状态映射、事件透传**，不拥有业务目标、不破坏内核约束机制。

## 新增工具原则（重要）

**不提前预建空目录、不提前铺摊子**。

所有新工具遵循：**用到再建、按需增量**。

必须同时满足以下条件才能放入 tools：

- 通用、可复用、不绑定任意业务场景

- 不属于范式内核逻辑

- 可被 examples / solutions 共同复用

- 属于工程配套能力，而非理论建模能力

---

## 边界禁止（绝对不放进 tools）

- 具体业务逻辑（归 solutions）

- 范式内核规则与核心算法（归 survx/ 内核）

- 仅用于单个 Demo 的专属代码（归 examples）

- 带场景定制的特殊对接逻辑（归对应 solution）

---

## 整体架构一句话

**内核定规则，tools 造基建，examples 演能力，solutions 出成果。**
